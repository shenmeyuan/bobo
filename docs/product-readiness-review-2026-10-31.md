# Bobo 产品可用性与继续投入判断

评审日期：2026-10-31。分析与规划：Astra；临时代码复现：GPT-6.1 Sol。本报告依据当前工作区（含未提交改动），不是仅审查 Git HEAD。没有修改功能代码，也没有启动真实模型或 Agent 任务。

后续实现记录：[记忆优化](memory-optimization-2026-10-31.md)、[自动接手授权与会话项目隔离](task-scope-and-fallback-2026-10-31.md)。下文保留初次评审发现；具体修复和验证状态以对应实现记录为准，不代表全部产品发布缺口已经解决。

## 先做判断

**用户已明确目前以个人任务为主，暂不考虑团队。值得再做一轮有退出条件的产品验证，不值得沿着“桌宠 + 所有 Agent 总控 + 通用记忆”继续铺功能。** Bobo 已有相当完整的本地执行、有限恢复、要求保留和证据版本机制；现在缺的主要不是能力数量，而是用户愿意采用的完整路径，以及相对于原生工具和直接竞品的实际收益。

当前适合作者自用和有开发者陪同的演示，**不适合宣称已经面向普通用户可用**。先修复下面两项 P0，再把最短闭环交给 5～8 位目标用户受控试用；签名分发、数据退出和支持材料完成前，不开放广泛下载。自动更新可以晚于首轮私测，不能把全平台发布当成此次验证的前提。

推荐首批用户：**macOS 上已交替使用 Codex 与 Claude Code、每周确实遇到长任务中断或切工具、愿意选择项目和核对交付的个人开发者**。这不是泛办公用户，也不是只想养宠物的人；“长任务和切换经常发生”本身仍需访谈验证。

推荐只承诺一个工作：**任务停下后，让我快速知道哪里需要处理，保留我已说清的要求和纠正，带着可复核的产物继续一次，并确认哪些检查仍有效。** 宠物可以保留为友好的提醒入口；是否保留常驻宠物应由用户控制，不应成为完成工作的额外负担。

## 已有价值，以及价值边界

以下是代码已有的工程能力，值得保留：

- 执行结束与验收通过分开表达，公开报告标记为未验证；没有把模型自报“完成”直接当作正确性证明。[状态文案](../src/lib/api.ts)、[报告档案](../electron/task-memory.mjs)
- 同工具优先原生 session；跨工具携带原始要求、纠正、检查与文件证据；原进程存在时阻止重复写入。[接续](../electron/agents.mjs)、[进程与目录检查](../electron/agents.mjs)
- 已声明输入、输出或验收条件改变时，历史检查保留但当前证据失效；必要上下文超预算时暂停，不静默删除要求。[证据有效性](../electron/workflow.mjs)、[预算门槛](../electron/agents.mjs)
- 外部观察默认关闭、只记录元数据；用量缺失显示未知；有限恢复不靠反复调用模型判断状态。[观察配置](../electron/session-observer.mjs)、[恢复器](../electron/supervisor.mjs)

**这些证明实现认真，不证明用户一定需要它，也不证明省 Token。** 仓库自己的早期试验：两种条件都 3/3 通过，附交接记录组反而多用约 37% Token；任务和样本都很小，不能推出广泛结论，但足以停止使用“天然省钱”的卖点。[已有试验](../docs/workflow-release.md)

## 当前竞品意味着什么

本节为官方资料核查，非安装实测。竞品功能存在不等于其可靠性已被独立验证；没有在其文档中找到某机制，也不能据此断言其一定没有。

| 对照对象 | 官方公开能力 | 对 Bobo 的约束 |
| --- | --- | --- |
| Codex/ChatGPT 桌面与 CLI | 浮层 Pets、任务状态与通知；长程 `/goal`；原生 resume；本地跨会话 memories。[Pets](https://learn.chatgpt.com/docs/pets)、[长任务](https://learn.chatgpt.com/docs/long-running-work)、[Memories](https://learn.chatgpt.com/docs/customization/memories)、[CLI](https://learn.chatgpt.com/docs/codex/cli) | 桌宠、长任务和一般记忆已有原生竞争。当前 Codex 文档会跳转到 ChatGPT Learn。 |
| Claude Code | 桌面并行会话/worktree、通知、用量与差异审查；CLAUDE.md/auto memory；状态与权限 Hooks。[桌面](https://code.claude.com/docs/en/desktop)、[记忆](https://code.claude.com/docs/en/memory)、[Hooks](https://code.claude.com/docs/en/hooks) | 同工具继续与记忆是强基线，不能只比较失忆的简单转发。 |
| Conductor（Melty Labs）与 cmux | Conductor 已提供多 Agent、独立工作区及 review/merge 流程；cmux 提供通知与跳转工作区。[Conductor](https://www.conductor.build/docs)、[Checks](https://www.conductor.build/docs/reference/checks)、[cmux 通知](https://cmux.com/docs/notifications) | 多 Agent 工作台、完成提醒、结果检查不是新类别。 |
| CodePet | 作者仓库公开描述桌宠、多 CLI、状态/额度、持久 Codex 会话、shared traces 与 `@agent` 交接聊天室。[作者仓库](https://github.com/nokryong/CodePet) | 最直接对位：“桌宠 + 多 CLI + 额度 + 共享轨迹”组合也不能声称独有；其成熟度与效果本次未验证。 |

因此可验证的差异不能是“也能记忆/通知/换 Agent”，而应是：**在明确断点中，Bobo 是否让用户少重述要求、少误信过期结果、少花人工恢复时间。** 特别是“中途纠正要求 + 输入文件随后改变 + 换工具继续”的组合场景，现有实现提供了可测试的抓手。这个组合不是已证明的独占技术；若只是记一段 Markdown 就能达到同等效果，Bobo 就没有必要承担独立桌面产品的复杂度。

## 从第一次打开到拿回结果：主要缺口

“事实”是已读代码支持的行为；“影响”是由行为推导的用户风险，不冒充已观察到的用户研究结果。P0 指交给新用户前应修复；P1 指形成稳定试用闭环需要完成。

### P0：聊天发起时的项目和权限没有固定

**事实：** `Brain.chat` 先将当前 workspace/allowEdits 放入模型上下文，但模型稍后返回 `dispatch_task` 时，又由 `AgentManager.dispatch` 读取当时最新全局设置。选择工作目录和修改编辑开关没有像切换对话那样检查 `brain.busy`。[上下文捕获](../electron/brain.mjs)、[工具派发](../electron/brain.mjs)、[读取当前设置](../electron/agents.mjs)、[目录切换](../electron/main.mjs)

**影响：** 在 A 项目发出请求，等待回复时切到 B，基于 A 上下文生成的任务可能在 B 执行；期间改变权限还可能让这次请求取得发起时没有的编辑能力。不能只用 UI 提示解决，主进程需要把请求、项目和权限绑定，或在设置改变后明确终止旧请求的派发。

**本地 mock 复现确认：** Sol 使用真实 `Brain` 与 `AgentManager`，将模型、子进程和 scope 探测替换为本地 mock。场景一：模型上下文为 A/只读，等待期间切到 B，实际派发任务的 workspace 和 spawn.cwd 均为 B，执行输入仍含 A 的要求。场景二：模型上下文为只读，等待期间打开编辑，实际派发变为 `workspace-write`。两个断言均通过。复现模拟 IPC 对设置的赋值，没有启动 Electron 或真实 CLI，没有在真实项目中读写；临时脚本和模拟配置已清理。P0 是产品发布优先级，不是漏洞严重度评分。

另一个相邻问题：对话没有 workspace 归属，切项目也不切对话；下一轮会把 A 的旧聊天与 B 的当前目录拼在一起。即便消除了竞态，仍要明确会话归属和切项目策略。[对话字段](../electron/conversations.mjs)、[聊天历史拼装](../electron/brain.mjs)

### P0：跨供应商接手默认全部开启

**事实：** 新存档默认 `superviseTasks: true`，`fallbackAgents: [codex, claude, trae]`。任务自动继承名单，限额后可选择其他已安装工具；新建任务只传执行器、要求和检查条件，没有运行前的名单确认。名单可以在设置或发出任务后的折叠区域修改。[默认值](../electron/state.mjs)、[继承名单](../electron/agents.mjs)、[自动换工具](../electron/supervisor.mjs)、[新建任务](../src/App.tsx)

**影响：** 用户只选择 Codex，也可能把任务内容交给 Claude/Trae 并产生另一账户的用量。“已获准接手”不应该由安装状态或默认勾选推定。新用户默认只允许原工具；其他工具由用户明确选定，发起前显示本次政策和尝试上限。旧存档默认名单与用户真实选择无法可靠区分，迁移必须有可理解的重新选择策略，不应悄悄解释为明确授权。

### P1：其余闭环缺口

| 用户环节 | 已确认的实现事实 | 影响与最小改进 |
| --- | --- | --- |
| 首次打开 | 主入口为聊天；无 Key 时回复要求配置 `.env`。直接交给 CLI 藏在“＋ → 交互方式”。设置中的“已配置”只是 Key 存在且配置形式检查通过；CLI 检测只找可执行文件，登录在任务运行时验证。[无 Key 路径](../electron/brain.mjs)、[CLI 入口](../src/components/DesktopPet.tsx)、[配置判断](../electron/config.mjs)、[安装检测](../electron/agents.mjs) | 第一次价值容易变成“先配置另一个模型”。首页直接给“连接已有 CLI”，选择目录、看到权限和能力状态即可使用；聊天 API 是可选项。区分已发现/版本支持/登录未知，支持本地无推理诊断；不能把 Key 存在标成连接成功。 |
| 继续已有工作 | 观察和托管是两条路径。Codex 最多读取 40 条当前目录记录，独立服务不保证另一窗口的实时状态；CC 仅有状态元数据；外部列表没有回原会话动作，也不接管。[读取](../electron/session-observer.mjs)、[列表](../src/components/ObservedSessions.tsx) | “不用迁移入口”的观察功能不能交付核心接续收益。先明确写清能力，支持可信的回原工具/复制会话标识。是否需要用户主动导入原始要求和阶段报告，用试用验证；不要为填补入口断层先做任意 IDE 接管。 |
| 失败与权限处理 | 未知错误、登录和权限问题停止自动恢复，这是正确边界；只读原任务不会因全局开编辑而升级。接续和验收要求用户先去设置选回原目录。[停止规则](../electron/supervisor.mjs)、[权限保留](../electron/agents.mjs)、[目录要求](../electron/agents.mjs) | 缺少完成动作：原工具登录后重试、定位原目录、明确以新权限建立新任务并保留来源。不要靠放宽原链权限“修复”；主按钮应随失败原因变化。 |
| 拿回结果 | UI 能列报告和文件变动，但文件路径只是文本；检查限 exists/contains/json/显式 Node 测试，缺少独立用户验收记录。[产物变动](../src/components/TaskWorkflow.tsx)、[检查种类](../electron/workflow.mjs) | 用户最终要看实际产物，而非翻账本。先做“在 Finder 中查看/打开安全产物路径、明确检查范围、用户确认或记录待改项”。不必立即加入所有语言测试，也不能把简单文件检查包装成业务正确性。 |
| 长期使用与退出 | 原子写入、0600 文件权限已有；存档损坏则报错退出。会话/任务和报告持续保存，已审查的 UI/IPC 没有导出、删除或恢复入口；撤下规则并不删除历史。[存储](../electron/store.mjs)、[消息](../electron/store.mjs)、[IPC](../electron/main.mjs) | 私测前至少明确保存位置、保留内容和手动备份/清除方法；扩展试用前提供可预览导出、按项目清除和可恢复备份。避免用户只能删整个存档、同时失去宠物历史。未做大历史规模性能测试，不能推断已经存在性能故障。 |
| 安装、升级与支持 | `package` 仅 `electron-builder --dir`，macOS identity=null；README 明确未完成签名分发，尚未选择 LICENSE。退出应用会停止自身任务。[打包](../package.json)、[mac 配置](../package.json)、[退出](../electron/main.mjs)、[发布说明](../README.md) | 首轮只支持 macOS 和明确 CLI 版本。公开发布前给可安装的签名/公证包、升级与回退方式、数据说明和分发条款；提供脱敏诊断导出。退出前说明运行中任务将停止。不要把未验收 Windows/Linux 作为已支持平台。 |

工作目录限制、最小环境和 `shell:false` 都不是全面系统沙箱；当前 README 已说明这一点，应该保留。相同目录写入锁也只覆盖 Bobo 管理的进程，不能对同时打开的原生 IDE 作出互斥保证。这里的改进目标是能力透明，不是新增泛化安全承诺。

## 下一版范围与门槛

| 阶段 | 必做结果 | 进入下一阶段的门槛 |
| --- | --- | --- |
| P0：可交给试用者 | 固定请求项目/权限；明确跨工具接手选择；项目切换不隐式携带旧任务上下文 | 无模型回放证明请求飞行中切项目/权限不会误派发；默认限额不换供应商；主动授权后才可跨工具 |

| P1b：证明有用 | 只验证“带约束和证据恢复工作”，记录人工时间、重复解释、违反纠正和错信过期证据 | 达到下文继续投入门槛，再投正式分发、更新和更广适配；否则收缩为辅助插件/开源小工具或停止 |

这三个阶段按退出条件推进，不承诺没有依据的交付日期。P1a 的样本和时间是此次建议的产品门槛，不是行业标准。

**此次明确不做：** 新增更多 Agent/豆包自动化、通用办公总控、任意 IDE 会话接管、后台无限自治、LLM 自动经验提炼、自动压缩研究、多平台同步、宠物社交/3D/语音、任意 shell 验收。保留已有实现但不继续扩张 Trae/豆包入口；首轮主界面聚焦 Codex 与 CC。不以“最低价模型路由”“硬费用上限”作为卖点，现有账本不支持这些承诺。

## 可由 GPT-6.1 Sol 接续的小任务

每项单独修改和审查，不借机重构整个 App；优先级按表顺序。当前工作区已有大量修改，实施时必须基于现状保留它们。

| 任务 | 最小范围 | 必要验收 |
| --- | --- | --- |
| S1 请求作用域固定 | Brain 发起时固定 conversation/workspace/allowEdits；工具执行校验上下文，飞行中设置变化不能改变目标或扩大权限。最小版本也可拒绝变化后的派发并明确提示重发 | 两个竞争时序回归：A→B、只读→编辑；不启动真实 CLI |
| S2 明确接手政策 | 默认仅原工具；新增任务前可选接手名单；主进程记录政策来源；对旧默认名单做明确迁移提示 | 未授权跨工具不会 spawn；明确选择才可接手；取消依然禁止重启 |
| S3 首次连接路径 | 空状态直达目录选择和现有 CLI；显示实际能力、登录未知、可选聊天配置；不自动发送付费探针 | 一个空存档 UI 路径，模拟 CLI；用户可跳过 API Key |
| S4 可行动的失败卡 | 按登录/权限/目录/预算/原进程未退出提供对应操作；保留原权限，新权限走明确新任务 | 复用既有失败 fixture 覆盖修复项；不为每条文案新建测试 |
| S5 交付与验收入口 | 安全解析产物路径后打开/定位；检查范围靠近结果；增加有时间/来源的用户验收记录 | 越界/符号链接目标被拒绝；用户确认不覆盖机器检查历史 |
| S6 数据与试用包 | 先完成可读的数据位置/备份说明与诊断脱敏，随后导出/按项目清除、签名发布 | 临时存档验证导出不含 Key；清理不影响其他项目/宠物；一次目标平台安装升级验收 |

S1/S2 是修复信任边界；S3～S5 是让现有能力能被用到；S6 按私测和公测分层交付。没有用户证据前，不把跨工具自动导入历史加入该清单。

## 最低必要验证与停止条件

本轮验证：`npm test` **101/101 通过**；`npm run build` **通过**（TypeScript + Vite）；另有上述两项无真实模型的竞态复现。没有跑七套 Electron 烟测，没有重新打包，没有真实 CLI/模型调用。这能证明当前已有测试与构建通过，不能证明新用户能用、供应商当前版本兼容或长期驻留可靠。静态审查也不替代实际首次启动观察。

后续实现只运行受影响单测和必要构建；涉及 IPC/首次连接时跑**一条**隔离 Electron 闭环。只有修改适配器或正式发布时才做目标版本的额外兼容验证。不要为了验证一个文案或文档改动重跑全套桌面测试。

产品试验分两步：

1. **先验证需求和可用性，不买新模型调用。** 找 5～8 位目标用户回顾最近真实中断，记录他们目前如何原生恢复、是否真的跨工具、有多少人工重述。P0 修复前只做历史案例、只读凭据或隔离演示，不让外部用户真实派发；修复后再让其用现有任务走通 Bobo。观察宠物是否降低注意力负担，还是挡住窗口；不要用“觉得可爱”代替工作价值。
2. **需求成立后才安排有预算的成对试验。** 固定仓库隔离副本、断点、底层模型、权限、CLI 版本和成本记录。基线至少包括熟练用户的原生 resume + 正常项目说明/手工交接，以及直接竞品的公开工作流；不能只与“丢掉历史直接重问”比较。同工具原生继续、跨工具接手分别报告，轮换试验顺序。

首轮只需覆盖四类断点：限额/可恢复中断、中途纠正与撤销、输入改动导致旧证据失效、只读权限或验收失败。主指标是**人工恢复分钟数、重复解释次数、违反有效要求次数、把过期证据当有效的次数**；Token、等待时间和调度开销为成本指标。不把任务历时当人工节省。需要付费的真实对照另定总预算与最大调用数，本轮未执行。

建议事先约定投入门槛：完成至少 12 组成对恢复样本后，Bobo 在多数样本中减少人工恢复，配对中位改善达到约 30%，且未增加错误项目、权限扩大、纠正遗漏或过期证据误判；至少 3/5 活跃试用者愿意在第二周主动把新任务交给它。这里的小样本只用于是否继续开发，不能发布“成功率提高 30%”之类统计营销结论。

如果用户实际很少切换、原生 resume 已足够，或者为了填写检查/记忆多花的时间抵消了收益，就停止扩大执行器和记忆系统。若用户只需要提醒，收缩为轻量状态工具；若只需要可信交接，优先导出可移植交接包或集成现有工具。**Bobo 的继续投入应由这次证明决定，而不是由还能添加多少功能决定。**
