# Bobo 工作记忆：真实文件执行试验与本轮修正

评测日期：2026-10-04；整理日期：2026-10-05。

**本轮找到了具体的接入故障，也验证了记忆机制能帮助完成小项目；尚未证明它比原生 Agent 更可靠或更省钱。** 三次重复的完整对照未完成，达到门槛后停止了新调用。未完成、输出不足和评测器故障都保留，不挑成功样本重跑。

## 1. 这次实际做了什么

不再只回答下一步问题，而是在临时目录里操作真实项目文件，最后由 Agent 看不到的独立 Node 检查器执行验收：

- CSV：修复解析和序列化，实现引号内换行、逗号、引号转义、CRLF、空单元格与往返转换，交付说明，保留输入。
- 交易导出：在旧 CSV 要求之后加入用户纠正，改成 JSON 数组和整数分，准确转换十进制金额，拒绝无效输入，交付实际 JSON。
- 依赖计划：暂停后外部修改输入数据，重新计算拓扑排序；检验环、缺失依赖、字典序和不修改输入对象。

每次分支恢复同一目录中的相同文件字节。准备阶段由模型读取已有实现并公开报告，然后停下；这是人为安排的阶段停点，不是数小时工作中随机发生的崩溃。三种条件分别保留完整会话历史、只交接公开报告、使用 Bobo 实际的档案与结构化交接代码。

## 2. 外部 Trae 对照首先暴露了接入故障

本机 Trae / Coco 的默认执行模型为 **GPT-5.4**，与 Bobo 调度模型分开，没有修改用户的模型配置。准备阶段回报 123277 Token；CSV 的原生接续回报 392561 Token，完整报告接续回报 162013 Token。两个分支都没有完成文件交付。

故障来自旧的自动批准工具名单：它包含 Edit / Write / Replace，却漏了当前 GPT 执行器实际使用的 **ApplyPatch**。公开报告及真实工具事件都记录了 `Permission denied to execute this tool`。原生分支还尝试走内部 Agent 路径，说明提示词约束不能代替工具层限制。因此该试验**不构成权限一致的记忆方法对照，不能用于排名**。

585000 已回报 Token 的接续门槛是在两次请求之间检查的；第二次请求从 515838 开始，结束后累计 677851，因此越过门槛后才停止，没有启动 Bobo 组。门槛不是执行中硬上限。

最早一次准备调用还因评测器把对象当作数组解析而中止。该基础设施故障不计作 Agent 失败，完整用量未知；该会话的提供方 trace 至少记录了 19126 Token，不能假装这次免费。

## 3. 固定模型、真实文件工具的试验

为了分开执行器故障与记忆选择，另用配置的 Model Hub **gpt-5.6-sol**，构建统一的最小文件工具执行循环。模型可列出、读取和写入临时项目文件，没有 shell、网络或子 Agent。会话组保留这个执行循环的公开历史，**不是 Codex、CC 或 Trae 的原生会话**。Bobo 组调用生产代码的档案和交接生成器。

| 项目 | 会话历史 | 公开报告交接 | Bobo 记忆交接 |
| --- | --- | --- | --- |
| CSV | 无可用最终报告；输出额度用满 | 验收通过，12020 Token | 验收通过，17322 Token |
| 用户改成 JSON／整数分 | 验收通过，9248 Token | 验收通过，12173 Token | 验收通过，13723 Token |
| 外部输入改变后的依赖计划 | 预算门槛中止，不能按完整任务评分 | 未执行 | 验收通过，11813 Token |

上表各组用量包含该分支全部模型与文件工具循环，不包含共同准备阶段。共同准备共 4239 Token；全部已执行调用共 **87308 Token**。每次调用输出上限 1800，最多九轮；CSV 会话组一次回报 1800 输出 Token 后没有可用的公开最终报告，也没有工具写入。原始失败记录保留。外部变动会话组在执行期间触及预算门槛，其部分产物不代表最终交付。

原计划每项三次，但实际只进入首轮，且最后两组未完整执行，**不能用 3/3、2/2 或 1/3 宣称哪种方法胜出**。Bobo 在三个小项目上完成了真实代码和产物验收，证明了机制可运行；在两个有完整公开报告对照的任务上，Bobo 总共使用 31045 Token，报告组 24193 Token，反而更高。没有配置价格表，Token 不是金额。

没有人工救援，没有真人使用工具的时间对照。零次救援不等于节省了多少人工分钟。测试不涉及原工具内部 compaction，也不证明多小时任务收益。所有产物和逐项验收记录保存在原始 JSON 中，失败和预算中止也保留。

## 4. 根据结果完成的产品修正

1. **修复 Trae 写入工具匹配。** 开启文件修改时批准 ApplyPatch；只读时显式禁止它。禁用未授权的 Agent / Task 委派，避免一个工具失败后绕路消耗大量 Token。
2. **识别结构化权限拒绝。** 支持 CC 的工具结果数组，以及真实 Coco 的顶层 `user / tool_result` 加嵌套 `content.content` 形式。确认拒绝后请求停止进程，显示需要处理，不按文件验收失败继续重试。助手正文、成功读取的引用文字不会被当成权限拒绝。
3. **减少交接中的管理信息。** 本地保留完整档案、用量和内部编号，执行器输入省去计费数据、预算统计、重复编号和重复报告长度。原始要求、纠正及撤销、验收、失效状态、当前变化、报告原文片段和档案路径／哈希继续保留。
4. **界面展示实际传输字符数。** 与本地完整记录的长度分开，继续明确字符不等于 Token。

三个重新构造的小项目中，执行数据包为 1489／1771／1553 字符，完整本地记录为 2169／2451／2233 字符。这里只核查了数据包长度与必需字段保留，**没有重新运行完整模型任务，不能说总 Token 已降低同样比例**。

## 5. 验证与用量透明度

- 本机真实 Trae 已用修正后的 ApplyPatch 创建随机标记文件，并通过 Bobo 的文件检查，回报 42958 Token。
- 权限流调试保留三次旧白名单复现，回报 88228、43130、87845 Token；它们揭示嵌套格式差异，不是记忆策略重复样本。最终用真实拒绝事件回放驱动本地真实子进程，验证进程退出、一次提示、不重试。这个最终回归不调用模型。
- 本轮已知用量合计 1027320 Token；最早评测器中止的完整用量未知，19126 只是其已知下界。不得将已知合计说成完整账单。CLI 的费用字段 0 不代表实际免费。
- 单元测试、构建和桌面回归另行记录在使用说明；它们不消耗在线模型。

修复能防止已知权限故障继续自动尝试，但尚未测得生产环境节省比例。没有再增加昂贵的摘要器、向量库或经验整理模型。下一轮应先确认所选工具可写、可执行必要验收，并给所有条件足够输出空间，完成预算内的一轮平衡对照后再扩展重复次数。

## 6. 如何复现

```bash
# 不请求模型
npm run eval:work-memory
npm run eval:project-memory

# 明确请求在线执行，消耗对应账户额度
npm run eval:work-memory -- --run --repeats 1 --token-limit 650000
npm run eval:project-memory -- --run --repeats 1 --token-limit 150000

# 不消耗在线额度：真实子进程回放 Coco 权限错误
npm run test:permissions
```

后续 CLI 脚本会先执行一次临时写入能力检查，失败就停止展开任务分支。首轮在未验证写入能力前直接展开昂贵对照，是评测安排上的失误；新的前置检查与拒绝停机处理用于防止复发。

后续脚本已采用修正后的工具名单、精简交接和更合适的输出额度；与上述探索版不是同一配置，不能把新的重跑混进旧结果。脚本默认 dry run，明确 `--run` 才执行。临时项目在结束后清理，不修改用户的 Bobo 存档或真实项目。工作进程中断时仍须检查脚本保存的自有 PID，不能批量终止其他 Agent。
