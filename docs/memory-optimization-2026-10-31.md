# Bobo 记忆优化：设计依据与实现验收

日期：2026-10-31。范围：个人任务；分析与审查使用 Astra，功能代码由 GPT-6.1 Sol 实施。保留现有工作区改动，不修改用户原生 Claude/Codex 记忆文件，不运行真实模型评测。资料以官方 Claude 文档和指定版本的 arXiv 原文核验；文献搜索脚本因本机 Python 版本问题不可用时，直接核查一手原文，没有安装额外依赖。

后续两项修复见[自动接手授权与会话项目隔离](task-scope-and-fallback-2026-10-31.md)。本页是记忆优化这一轮的实现记录，文中“未在本轮修改”的边界不覆盖后续工作。

## 本轮解决什么

本轮选择三项可直接改善现有行为的优化：**用户明确替换旧规则、模型按需读取有界的记忆结果、紧预算下优先携带最新工作报告**。中文检索与请求作用域检查作为这些路径的必要支撑。

不改变原始要求、纠正、撤销和必要证据的保护规则；不因所谓“相关性低”静默删除它们。没有引入向量数据库、每轮付费摘要、自动知识图谱或未经用户确认的经验生成。原因是现有问题可用确定性逻辑修复，这些新系统尚无本项目效果证据。

## 代码中确认的问题与处理约定

### 1. 保存新规则不能表达替换，重复判断还忽略类型

旧接口只有新增和撤下：用户保存“金额改用整数分”不会自动使之前相反的有效规则失效。新增去重只比较项目、正文和 active 状态；相同文字从“参考位置”保存为“工作规则”也可能返回原参考条目，导致用户期望的常驻指导仍被当成可选内容。

新增显式替换操作，要求指定当前条目、原项目、预期版本及新正文/类型。所有验证成功后一次保存：旧项撤销，新项生效，以 `supersedes/supersededBy` 关联；旧正文仍保留。旧界面版本、错项目、撤下项和含糊的重复目标不得部分成功。达到有效条目上限时，净数量不增加的替换仍可执行。撤下新条目不会复活旧条目。

界面让用户看清旧内容和新内容，可取消；保存后管理列表保留新旧条目和替换标记。这不是额外开发了一套完整历史版本浏览器，也不在后台自动推断语义矛盾。既有存档不需要重新录入，新增关系字段向后兼容。自动检索与接续继续明确携带撤销，不能把版本关系当作省略旧规则撤销信息的理由。

### 2. 管理列表直接进入模型工具，历史会膨胀并重新注入旧正文

旧 `search_project_memory` 将 `listProjectMemories` 返回的完整对象截取 8 条后直接传给模型。条目数量有限，但每条 `history` 可以增长；scope、历史正文和其他管理字段都被带入，没有总文本/Token 门槛。这也可能使下一轮触发既有 24,000 本地估算 Token 输入门槛，无法继续读取结果。它还保留无匹配的常驻规则，可能挤掉实际搜索对象。

已将两个用途分开：管理列表保持完整；模型 search 只返回 ID、版本、类型、状态、短原文预览与替换关系，每页最多 8 条、单条最多 160 个 Unicode 字符、整页最多 1,000 本地估算 Token，并提供继续读取位置。预览标明不完整，不能当作完整规则。`read_project_memory` 在相同项目内按 ID 读取完整当前正文、状态和关系，默认不返回历史；其他项目 ID 拒绝访问。

原本自动注入的工作规则、偏好保持必需内容；**有效参考位置可选，撤销项（包括 reference）必需**。统一这一判断，防止旧参考虽已撤下，却在下游预算装配中被忽略，导致原生会话仍沿用它。**此次没有解决无限增长的撤销记录成本**，也没有默默降低其优先级；必要内容超预算仍暂停。若以后做按原生 session 的撤销增量传输，必须先建立“哪些版本曾实际交给该 session”的可靠记录。

### 3. 紧预算时旧报告可能比最新阻塞优先，中文问句匹配不一致

任务由 `unshift` 保存为最新在前，而旧交接代码倒序加入报告片段，注释虽写 latest first，实际会让旧报告先占可选预算。报告片段检索又把连续中文问句当作长精确词，与项目记忆已有的中文二元词处理不一致，容易漏掉位于报告中部的相关原文。

明确报告的时间排序与选择顺序，先尝试放入最新报告的完整原文片段，再处理参考和旧报告；呈现顺序不替代选择优先级。共享有上限、去重的中英文词汇拆分，用中文词组重叠改善召回，保留原文位置和 UTF-16 偏移，不生成摘要。它是词汇匹配，不是语义搜索，仍可能漏掉没有共同词的同义表达。

### 4. 延迟返回的工具不能操作新切换的项目

记忆工具之前读取执行当下的全局项目，而模型请求已经使用发起时的项目上下文。等待期间切目录，可能将 A 的记忆写到 B；同一问题也影响任务派发与权限。

本轮采用保守边界：请求发起时固定项目/权限上下文，在模型返回后、执行工具前检查；发现变化即停止本轮旧上下文的工具阶段，明确提示重新发起，不伪装成网络错误。已经完成的操作不回滚，也不重放。该检查不等于给历史会话增加了项目归属；此前“切项目后仍可能携带旧聊天”的产品问题不因此宣称全部修复。此前评审中的“跨供应商接手默认全选”也未在本轮修改，不能将这次记忆优化当作全部 P0 已完成。

## 验收与证据

只验证这次修改实际影响的行为：

- 替换的原子性、版本冲突、跨项目拒绝、旧档重启、有效条目上限和撤下后不复活。
- 大量历史不会进入模型搜索响应；输出预算、分页及按 ID 读取完整当前正文有效。
- 紧预算下最新阻塞信息优先，硬性要求、撤销和必要证据仍完整；原有输入变化导致证据失效的回归保持通过。
- 中文问句能命中对应报告中部，所有摘录仍是原文精确片段且不超过预算。
- 模拟模型等待期间切项目或增加编辑权限，旧请求不执行记忆写入或 Agent 派发。
