# 自动接手授权与会话项目隔离

日期：2026-10-31。按用户“解决吧”的要求处理前次评审剩余两项：默认跨工具接手名单、历史会话未绑定项目。范围仍为个人任务；Astra 设计和审查，GPT-6.1 Sol 修改功能代码。保留此前所有工作区改动，不修改真实存档，不启动真实模型或 Agent 任务。

## 自动接手：默认只允许原工具

需要分清三个动作：

| 动作 | 授权含义 |
| --- | --- |
| 用户在界面明确选择另一工具接续一次 | 允许这一次接续，不自动把该工具加入未来恢复名单。 |
| 用户勾选全局或某项任务的接手工具 | 全局选择只作为未来新任务的默认；任务选择只适用于该任务链。明确记录界面操作来源。 |
| 调度模型为真正的新任务选择一个执行器 | 维持原有新任务选择能力，不把它解释为该任务未来可在所有工具间自动切换。 |

新用户的额外接手名单为空；每个任务仍包含原执行器，可在已有次数和停止条件内同工具恢复。限额时没有其他明确授权的执行器就暂停，显示需要用户选择，而不是看到电脑上装了其他 CLI 就自动发送过去。

模型可以保持或收窄既有名单、暂停照看；扩大名单只接受明确的界面入口。模型试图向未授权工具接续或扩大名单时，主进程拒绝，并结束这轮工具阶段，避免同一轮在收到拒绝后将续接伪装成新派发重试。此处不引入自然语言意图分类器，也不声称已经形式化证明所有“新任务”请求的用户意图。

恢复器在选择目标时和真正启动下一次尝试前都检查策略。撤销目标授权之后，旧 pending 不能继续生效；手工构造无有效授权标记的旧任务，也不能被当作已同意跨工具。停止或撤销不等于杀掉用户没有要求停止的正在运行进程。

## 旧接手名单只迁移一次

旧存档没有区分“程序默认全选”与“用户主动选择”，因此不能根据列表内容猜测授权。迁移检查原始保存数据中的标记，不能在合并新默认值后把旧存档误判为新版。

- 清空缺少可验证授权来源的旧全局额外名单，根任务回到原工具范围；保留旧列表作为迁移记录。
- 使不再获准的跨工具 pending 失效，保留任务历史和已经运行的进程。
- 展示一条非阻塞说明：旧名单缺少明确授权记录，现仅原工具，用户可重新选择。说明可关闭，状态持久化，不反复询问。
- 后续界面明确选定的策略保存新标记，重启不再覆盖用户选择。

这是一项保守的一次性迁移：旧版曾主动配置过的用户也可能需要重新勾选。相比继续把所有旧名单认定为授权，这个代价可理解且有明确恢复入口。

## 会话：按实际工作目录绑定

新会话的作用域只有三种清晰状态：绑定某个规范化工作目录、没有选择项目的一般聊天、旧版未绑定的历史会话。项目会话使用 canonical worktree 路径，不用 Git common directory 合并聊天；同仓库不同 worktree 的会话彼此隔离，项目记忆既有的仓库级共享规则不变。

有效目录取当前设置，设置为空时读取当前 `.env` 的 `BOBO_WORKSPACE`。没有配置目录才是一般聊天；目录已经配置但丢失、无法访问或符号链接改变，不能悄悄当成一般聊天继续。

| 用户操作 | 对话行为 |
| --- | --- |
| 在设置中切换 A → B | 打开 B 最近可用会话；没有则新建空会话。A 消息和草稿不进入 B。 |
| 新建对话 | 绑定当前有效工作目录；没有目录则创建一般聊天。 |
| 从历史列表选择 A，但当前项目是 B | 可以查看，明确标为其他项目历史；不自动改变当前目录，不直接发送。可切回 A，或在当前项目新建对话。 |
| 查看旧版未绑定会话 | 保留消息、搜索和已有任务关联，只读回看；新工作从当前项目的干净会话开始，不猜测整段历史属于哪一个项目。 |
| 外部修改 `.env` 或目录失效 | 即使界面尚未刷新，发起请求时也会重新校验；不使用旧会话在新目录执行。 |

不自动把旧历史“绑定到当前目录”，因为历史中可能已经混合多个项目。也不删除历史或把已有任务重新归属于一个猜测的项目。旧任务接续仍可携带该任务自身原始要求、纠正和证据，不会因此注入整个未绑定聊天记录。

## 请求期间切项目：回复仍写回原会话

仅在界面切换新会话还不够：旧请求可能正在等待模型返回。每次聊天固定发起时的 conversation ID、目录和权限；所有正常回复、错误说明、额度快捷回复以及中止提示写回原 ID。此时用户已在 B 查看对话，A 的回复也不会混入 B。

发起请求携带界面所看到的预期会话/项目，主进程先校验，再写用户消息或请求模型；否则后台已经切到 B 而旧界面仍显示 A 时，仅检查后台自己的 B 状态仍会投错项目。工具阶段重新校验目录、权限、活动会话。任何一项变化，就停止旧请求的工具阶段，保留已有记录并解释需要在当前项目重新发起。不能把作用域中止包装成网络错误，也不能自动重放已完成的操作。发送失败恢复草稿也按发起会话 ID 处理，不将 A 的失败文本恢复到 B 的输入框。

直接从界面派发 CLI 任务也检查会话关联，避免 B 的新任务挂到 A 或旧版未绑定会话。续接则保留原任务链的历史关联。

## 防止从其他上下文入口绕回旧项目

会话隔离不只过滤聊天数组。模型使用的任务概况、报告、工作流和任务操作按当前规范目录过滤或校验；当前项目不能通过已知 task ID 读取另一项目的报告。模型的外部会话观察也按项目过滤。界面仍可回顾历史总览，不因模型读取限制丢失用户记录。

全局宠物日记中含有工作任务标题，因此模型默认上下文只保留非工作日记；工作信息通过当前项目的任务工具获取。账户额度属于全局账户信息，仍可查询。主进程执行这些规则，界面提示和模型系统提示不代替校验。
