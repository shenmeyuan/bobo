# Bobo 接续与验收：实现与首轮实测

> 历史版本记录：下文描述第一轮人工接续。后台照看、Trae 与纠正留存更新见 [当前版本说明](supervision-release.md)。首轮评测数据和局限仍然有效。

日期：2026-10-04

## 现在可以怎样使用

点击桌面宠物，打开任务列表，进入一项已经结束、中断或失败的任务，在「接续与验收」中操作。大页面的任务详情也有相同入口。

1. 展开「检查条件与接续预算」，填写工作目录内的相对文件路径。支持文件存在、包含指定内容、JSON 可解析，可添加多项。保存条件后，点击「核查当前产物」。新建任务的窗口也可以预先填写交付文件。
2. 展开「让另一个 Agent 接着做」，选择 Codex 或 Claude Code，按需补充下一步，再点击「带着进展接续」。也可以对 Bobo 说：“把刚才失败的任务交给 Claude Code 接着做。”
3. 接续保留最初需求、用户配置的检查条件、之前的结果摘录、实际文件变更、失败原因和尝试关系。接续任务完成后，会自动运行已经配置的文件检查；仍可手动重新检查当前文件。
4. 查看跨尝试执行 Token、关联调度 Token 和缺失情况。可以限制尝试次数，或设置接续前的已知 Token 阈值。

原工作目录必须仍在设置中选中。首次执行为只读时，接续不会因为后来开启了编辑权限而自动升级权限。豆包仍为人工转交，不纳入自动 CLI 接续。

## 已实现的机制

| 能力 | 实际行为 |
| --- | --- |
| 持久化任务链 | 每次尝试独立保存，关联根任务和前次尝试；旧任务仍可使用。尝试与用量不再因超过 100 条而截断。 |
| 幂等接续 | 同一个父尝试重复点击只返回已创建的后续尝试；继续失败则从最新尝试接续。 |
| 进程退出等待 | 取消发出终止信号后，仍等待实际 close；必要时升级终止。原进程未退出不能接手。保存 PID，重启后检测到原 PID 仍存在时先阻止接续。 |
| 写入互斥 | 同目录涉及写入的执行不并发，避免两个 Agent 同时改同一组文件。只管理 Bobo 跟踪的进程，不能锁住用户或其他应用写文件。 |
| 文件证据 | 执行前后记录有限范围内的文件 SHA-256，交接时比较是否再次发生变化；摘要和哈希都不等于内容正确。 |
| 验收 | 不执行模型提供的任意 shell 命令。运行用户设置的确定性文件检查，保留结果、时间与文件指纹；执行结束与检查通过分别展示。 |
| 用量记录 | 保留 CLI 原始 usage；执行尝试累计与关联模型调用分别统计，缺失为未知。共享调度开销明确标注，跨任务相加不能重复计费。 |
| 接续阈值 | 默认最多 3 次尝试，可设置为 1～10。Token 阈值在下一次尝试前检查；配置阈值且有未知用量时阻止接续。 |
| 对话调度 | SP 升级为 bobo-keeper-v2。用户要求接续时调用 resume_task，查询用量/记录调用 get_task_workflow，运行检查调用 verify_task。 |

## 首轮真实模型对照：没有发现省 Token

模型为用户配置的 Model Hub `gpt-5.6-sol`，实际响应标识 `gpt-5.6-sol-2026-07-09`。三个隔离数据处理题，每题两个条件，每条件一次；交替运行顺序。

两组都有相同的原始需求、可列出/读取/写入的文件工具、原始数据和预先完成的 summary.json，需要接着交付 report.md。转发组只获得原始需求；交接组额外获得结构化检查点。两组共同的规则均要求检查已有产物、避免无用重写。验收通过程序检查实际工具写出的文件，而不是模型口头答复。

| 条件 | 通过 | 输入 Token | 输出 Token | 总 Token | 模型请求 | 重复写已有产物 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 简单转发 | 3 / 3 | 4122 | 459 | 4581 | 12 | 0 |
| 附交接记录 | 3 / 3 | 5740 | 537 | 6277 | 11 | 0 |

交接组多消耗 **1696 Token，约 37.0%**。整个小试验共使用 10858 Token。即使模型调用少一次，交接上下文也可能让总消耗上升。没有观察到重复写入的改善；不能据此宣称更高质量、更低成本或更少返工。

局限：样本极小，未做显著性检验；两组接收者使用同一模型，不是真实 Codex/Claude Code 的交叉实测，也没有真人基线。文件工具作用于内存中的隔离工作区。前序检查点为预置，两组共同的前序成本未计；包含交接文本、全部接收方模型轮次与工具回传的 Token，没有额外付费摘要器。因此这是一项交接信息的初步对照，**不是完整产品收益评测**。

据此保持：简单任务默认直接执行；仅在用户要求接续时附加交接数据。后续应在长任务中断、约束遗失和错误自报完成这些目标场景增加样本，与熟练用户人工切换及最强单 Agent 对照；当前没有证据证明 Bobo 优于真人选择 Agent。

## 验证与边界

34 项自动化测试通过，包含权限保留、幂等、退出等待、预算、未知用量、文件越界、验收失败及存档恢复。TypeScript/Vite 构建通过。

真实 Electron 工作流测试使用实际本地测试子进程，跑通 Codex 适配器失败 → Claude 适配器接续 → 所列文件检查通过 → 两次执行合计 50 个模拟 Token → 重启保存。该测试验证适配器与 UI，不冒充真实供应商 CLI 的能力或用量。

仍需明确的限制：

- 当前接续由用户点击或对话触发，没有后台自动换工具或无限重试。
- 文件扫描只覆盖非隐藏普通文件，排除依赖、构建输出与密钥，最多 500 个文件、单文件 2 MB、合计 16 MB；交接只传前 30 项变动及前 4000 字符结果。大目录清单不完整时必须重新检查，不能据缺失推断文件不存在。
- 文件存在、文字包含、JSON 可解析都只是局部验收。尚无测试命令执行器、业务语义判定器或整体验收判定。
- Token 阈值不是运行中的硬性费用上限；当前请求、未回报用量和无法关联的闲聊不能视作完整任务账单。未提供价格的调用不估算美元成本；订阅剩余额度仍需手动记录。
- 文件修改后，历史验收仅代表记录时间的版本；可以重新核查。正常退出会停止 Bobo 的子进程；异常退出或 PID 被复用时，可能需要用户处理原进程后再接续。

复现命令：`npm test`、`npm run test:desktop`、`npm run test:workflow`。`npm run eval:handoff` 会真实调用当前模型账户；默认在 30000 已回报 Token 处停止启动下一次请求，每次输出上限 900 Token。原始小试验结果保存在 `work/handoff-pilot.json`。
